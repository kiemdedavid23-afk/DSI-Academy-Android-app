# Fiche L6 : formations

**Sources :** plan étape 4 révisée ; API.md (`GET /content/:id/components/tree`) ; fiche L4b (le moteur refuse la livraison d'une formation : `TRAINING_HAS_NO_ASSET`).

## Livré
- **Maison Formations** ouverte dans le hub : découverte réutilisée (catalogue, catégories, recherche) avec ses stores de type `training`. Fiche détail : bouton « Voir le programme ».
- **Programme** : l'arbre de composants est aplati en sections (formations imbriquées) et modules, trié par position, profondeur max 10, boucle vers un contenu déjà vu ignorée (`logic/formationTree.ts`).
- **Un appel de livraison par module** : toucher un module ouvre le lecteur existant avec l'**id du module** (livre → lecteur de livres, audio/vidéo → lecteur Media3 ou YouTube). L'id de la formation n'est jamais envoyé à `/deliver`.
- **Progression** : lue par module (la progression des lecteurs, seuil 97 % = terminé), résumé « x / y modules », bouton « Commencer » / « Continuer » (premier module non terminé). Relue à chaque retour sur l'écran.
- **Reprendre** : la formation enregistre son pourcentage et une entrée du hub (`formations`) qui mène à sa fiche.
- Favoris : maison `formations`.

## Décisions
1. Une formation est terminée quand tous ses modules atteignent 97 %.
2. Un module non livrable (Telegram, Mega…) montre l'erreur du lecteur à l'ouverture ; il n'est pas masqué du programme.
3. Pas d'ordre imposé : on peut ouvrir n'importe quel module.

## Limites connues
- Pas de verrouillage de modules, pas de quiz ni d'évaluation, pas de certificat.
- Un module YouTube n'a pas de progression (limite de L5) : il ne compte jamais comme terminé.
- La progression d'un module ouvert hors formation compte aussi (même id).
- Non exécuté ici : typecheck, lint, jest, essai sur APK.
