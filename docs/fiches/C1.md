Source : RAPPORT-INTEGRATION-WORKER-COMMUNAUTE.md (§7 à §10, §15) ; site : `services/api/community/communityClient.js`, `houses/community/communityErrors.js`, `shared/community-profile/communityProfileErrors.js`.

## Règles relues avant de coder
R-NET-1 (aucune adresse hors du registre : le service `community` existait déjà, rien n'est écrit), R-NET-2/8/9 (chemins relatifs, `X-Access-Proof` par défaut), R-NET-10 (aucun log), R-LAY-5/6 (écrans sans API ; seuls les stores importent `core/api`), R-DATA-1/2/3, R-SEC-4, R-I18N-1 (clés du site reprises), R-TEST-LOC (tests à plat dans `__tests__/`).

## Contenu
- `core/api/endpoints/community/` : `common.*` (échecs typés, codes → nature de l'échec, preuve absente = échec local), `me.*` (GET /me).
- `shared/community/` : clés d'erreur FR/EN (site repris), décision de démarrage `communityGate`.
- `shared/store/communityMeStore.ts` : état communautaire du membre, purgé à la déconnexion.
- `contracts/community/` : fixtures tirées des exemples du rapport.
- Tests : `community.mapper`, `community.api`, `community.errors`.

## Choix
1. Pas de rejeu automatique sur `401 ACCESS_PROOF_EXPIRED` : l'app ne connaît aucune route de renouvellement de la preuve côté Paiement. L'échec est typé `unauthorized` (comme Boutique/Marketplace). **Point ouvert D9.**
2. Écriture jamais rejouée à l'aveugle ; `RATE_LIMITED` signalé au `rateLimitGate` par le client HTTP existant.
3. Preuve périmée + abonnement terminé = erreur d'abonnement, pas de session (règle du site).
